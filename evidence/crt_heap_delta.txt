IOCP 채팅서버 — 메모리 힙 증가량 측정 (Debug CRT, _CrtMemDifference)
============================================================
무엇을: 부하 시작 시점과 종료 시점의 힙 상태를 비교해, 해제되지 않고 남은 메모리 양을 잰다.
방법  : main.cpp 에 측정점 두 개(s1=시작, s2=끝)를 넣고 _CrtMemDifference 로 차이를 출력.
빌드  : Debug 빌드 x64 (/MDd) — Debug 빌드의 C 런타임(CRT)이 힙을 추적해 준다.
부하  : DummyClient --auto 500 (접속 → 해제 무한 반복).

아래 블록은 Debug CRT 가 그대로 찍은 원본 출력이다. (손대지 않은 증거)
읽는 법:
  - Normal Blocks 의 바이트 = 시작~끝 사이에 해제되지 않고 남은 메모리 (누수 후보)
  - Total allocations       = 그동안 할당된 메모리 총량 (해제된 것까지 포함한 누적)

------------------------------------------------------------
[1차] 시작점 s1 = 부하 걸기 전 (메모리 풀이 아직 안 커진 상태)
------------------------------------------------------------
0 bytes in 0 Free Blocks.
18787396 bytes in 22760 Normal Blocks.      <- 약 17.9 MB 남음
76820 bytes in 108 CRT Blocks.
0 bytes in 0 Ignore Blocks.
0 bytes in 0 Client Blocks.
Largest number used: 18903464 bytes.
Total allocations: 4100471982 bytes.        <- 누적 약 3.8 GB 할당
=> 남은 양 17.9MB / 누적 3.8GB = 0.5%. 대부분은 세션·버퍼 풀이 처음 한 번 커진 분량이다.

------------------------------------------------------------
[2차] 시작점 s1 = 워밍업 후 (풀이 다 커진 뒤, 's' 키로 측정점을 다시 찍음)
------------------------------------------------------------
0 bytes in 0 Free Blocks.
2253548 bytes in 686 Normal Blocks.         <- 약 2.15 MB 남음
-6204 bytes in -9 CRT Blocks.
0 bytes in 0 Ignore Blocks.
0 bytes in 0 Client Blocks.
Largest number used: 2273364 bytes.
Total allocations: 18558959012 bytes.        <- 누적 약 17.3 GB 할당 (접속·해제 51만 번)
=> 남은 양 2.15MB / 누적 17.3GB = 0.012%. 686개 블록뿐이고, 접속·해제 횟수(51만)에 비례해 늘지 않는다.

------------------------------------------------------------
결론
------------------------------------------------------------
- 1차에서 남은 17.9MB 중 대부분(약 15.7MB)은 풀이 한 번 커진 분량 -> 기준점을 워밍업 후로 옮기니 사라진다.
- 2차에 남은 2.15MB 는 누적의 0.012%, 접속·해제 횟수에 비례하지 않는다 -> 풀이 조금 더 커졌거나, 프로그램이 끝까지 들고 있는 상주 메모리다.
- 접속·해제 한 번당 메모리가 쌓이는 누수 패턴은 발견되지 않았다.
- 윈도우 성능 모니터(perfmon)로 잰 2시간 메모리 변동 0.4% 와도 일치한다.
